# DOCUMENTS THAT COMPILE AT A CERTAINTY LEVEL AND DO NOT MATCH THE ENGINE.
#
# The certainty levels promise agreement, so every line here is a broken promise, not an excuse.
# They are named rather than skipped so the gate still fails on anything NEW, and so the list can
# only shrink by fixing something. The o3 pipeline already demotes each of these to -O0, so the
# BEHAVIOUR is the engine's — what is wrong is the claim that -O1 needed no such demotion.
#
# One document per line: <Style>/<Name>  # reason

Basic/DelayButton   # COMPLETION ORDER. Not child order (the first reading, disproved) and not
                    # layout order (the second): the two ClippedText siblings are built in the
                    # engine's order, get the right bindings, and agree on every property either
                    # side ASSIGNS — visible, clipX, clipWidth, height, implicitHeight, y, text.
                    # They exchange baselineOffset, which NEITHER side assigns: QQuickText freezes
                    # it at the FIRST layout and never recomputes it on a later resize. Probed step
                    # by step: dc0 completes while the group is still 0 high and lays out at
                    # ascent - height/2 = 5.34375; dc1, appended into a group that already has a
                    # height, gets the ascent itself, 14.84375. The engine is the mirror.
                    # THE CAUSE IS KNOWN AND THE FIX IS WRITTEN: QQmlObjectCreator::finalize drains
                    # its created-object stack with pop(), so parser-status objects complete in
                    # REVERSE creation order, per level — we complete each child as we create it.
                    # Reversing it reproduces the engine exactly on both styles.
                    # WHY IT IS NOT LANDED: it removes an accident that was hiding two other gaps,
                    # and costs more than it gains until they are closed (measured over the full
                    # matrix: 231 compiled -> 227). A binding like `contentWidth:
                    # contentItem.contentWidth` is never wired, because `contentItem` is declared as
                    # an `Item` and Item has no contentWidth, so (1) the leaf connection needs the
                    # notify resolved from the object rather than the static type and (2) the read
                    # is not recorded as a deep read at all when the member is unknown on that type,
                    # so nothing asks for the leaf.
                    # BOTH ARE NOW LANDED — bindLeafProp and propAny, in the commit that closed the
                    # 516 refused reads across Qt's five styles. The reversal was last measured
                    # against a tree that had NEITHER of them, so the -4 it cost is a number about a
                    # compiler that no longer exists: it has to be measured again before it can be
                    # judged. Branch `wip/completion-order`.
Fusion/DelayButton  # The SAME defect, the same two values exchanged — one cause, two styles,
                    # because both DelayButtons are written the same way. Two lines rather than one
                    # so the gate keeps naming each style it actually shows up in.

# WHAT WAS HERE AND IS NOT ANY MORE. Judging -O1 over all five styles first found SEVEN documents,
# and six of them came down to three rules the compiler was missing rather than to six quirks:
#
#   * a binding that dereferences null must write NOTHING (JS throws; the engine keeps the default)
#   * QML's default for `property color` is OPAQUE BLACK, where a default-constructed QColor is
#     INVALID — different values that print differently
#   * a document's IMPORTS must be loaded, not only the module the document lives in, because a
#     module carries its resources
#

# CheckIndicator all agree with the engine now. Naming them here would have hidden three real gaps
# behind five well-documented excuses, which is the failure mode this file is one step away from.
